# מערכת הזמנות לאירועים: אפיון ותכנית עבודה

## רקע

בונים מערכת לעסק שיוצר הזמנות דיגיטליות לאירועים (פרטיים ועסקיים), **שולח אותן למוזמנים** ועוקב אחרי אישורי ההגעה.

התכנית מבוססת על תכנית העבודה של [`shyoni7/invitation-system-yoni`](https://github.com/shyoni7/invitation-system-yoni) (קובץ `docs/work-plan.md` שם), שכבר מומשה שם עד שלב 6. ההבדל המרכזי: שם הוחלט במפורש "אין שליחת הזמנות מהמערכת" (קישור אחד לכל אירוע שמופץ ידנית). אצלנו שליחת ההזמנות היא חלק מהמטרה, ולכן נוספו רשימת מוזמנים, קישור אישי לכל מוזמן, ושלב שליחה (שלב 4 למטה).

## ארכיטקטורה

### מחסנית
- **Frontend + Backend:** Next.js (App Router, TypeScript), Tailwind CSS
- **DB + Auth + Storage:** Supabase (Postgres, Auth לעובדים, Storage למדיה)
- **אימייל:** Gmail עם סיסמת אפליקציה דרך `nodemailer` להתחלה (כמו שמומש ברפו המקור, עד ~500 מיילים ביום). מעבר ל-Resend עם דומיין מאומת כשהנפח גדל
- **וואטסאפ:** קישורי `wa.me` בשלב הראשון. אופציונלי בהמשך: WhatsApp Business Cloud API עם תבנית הודעה מאושרת
- **תזמון:** Vercel Cron (בתוכנית Hobby פעם ביום; בתוכנית Pro אפשר כל שעה)
- **i18n:** `next-intl`, השפה נשמרת בעוגייה ולא בכתובת, כך שלכל אירוע ולכל מוזמן יש קישור אחד
- **ייצוא וייבוא Excel:** `exceljs` בצד השרת
- **אירוח:** Vercel

### מבנה נתונים (Supabase)

כל הטבלאות עם קידומת `inv_` (כמו ברפו המקור), כדי שאפשר יהיה לשתף פרויקט Supabase עם אפליקציה אחרת.

```
inv_staff               עובדים מורשים (user_id, email, display_name)

inv_events
  id, slug (ייחודי), title, event_type (private/business),
  description, date_time, venue_name, address, lat, lng,
  template_id, media_url, primary_color, gift_link_url,
  invitation_message (נוסח ההודעה שנשלחת עם ההזמנה),
  reminder_offset_hours, reminder_sent_at, rsvp_deadline,
  max_guests, allow_public_link (האם הקישור הכללי פתוח),
  created_by, created_at, updated_at, is_active

inv_invitees            (חדש) רשימת המוזמנים
  id, event_id, full_name, phone, email, group_name,
  expected_guests, token (ייחודי, לקישור אישי),
  status (pending / sent / opened / confirmed / declined),
  first_sent_at, last_sent_at, opened_at, responded_at,
  created_at, updated_at

inv_registrations       אישורי הגעה
  id, event_id, invitee_id (nullable, מקושר כשנרשמו מקישור אישי),
  full_name, phone, email, attending (bool),
  guest_count, guest_names (jsonb), notes,
  source (invite_link / public_link / manual),
  created_at, updated_at

inv_message_log         (מורחב מ-email_log) יומן שליחות
  id, event_id, invitee_id, registration_id,
  channel (email / whatsapp / sms), kind (invitation / reminder / nudge / test),
  to_address, status (sent / failed / clicked), error, created_by, created_at

inv_tables, inv_registration_tables   (שלב אחרון) שולחנות
```

- מניעת כפילות: אינדקס ייחודי על `(event_id, phone)` ב-registrations וב-invitees. הרשמה חוזרת עם אותו טלפון מעדכנת את הקיימת.
- קישור הרשמה למוזמן: בהרשמה מקישור אישי לפי `token`; בהרשמה מהקישור הכללי מנסים להתאים לפי טלפון.
- RLS: כל הטבלאות פתוחות רק לעובדים (`inv_is_staff()`). הצד הציבורי עובר דרך פונקציות SQL מאובטחות (`security definer`): `inv_get_public_event(slug)`, `inv_get_invite(token)`, `inv_register(...)`. המוזמן לא צריך חשבון ולא יכול לקרוא נתונים של אחרים.

### שליחת הזמנות (החלק החדש)
- **אימייל:** מייל HTML בעברית/אנגלית עם תמונת ההזמנה, פרטי האירוע וכפתור "לאישור הגעה" לקישור האישי. שליחה לכל המוזמנים, לקבוצה, או למוזמנים שנבחרו. שליחה במנות קטנות כדי לא לחרוג ממגבלות Gmail, וכל שליחה נרשמת ב-`inv_message_log`.
- **וואטסאפ (wa.me):** במסך המוזמנים כפתור לכל מוזמן שפותח וואטסאפ עם הודעה מוכנה (שם, אירוע, תאריך, קישור אישי). אחרי לחיצה המוזמן מסומן "נשלח". מצב "שליחה רציפה" שעובר מוזמן אחרי מוזמן.
- **מעקב:** פתיחת הקישור האישי מסמנת `opened_at`; אישור או סירוב מעדכנים את הסטטוס.
- **תזכורת למי שלא ענה:** כפתור ידני + אפשרות אוטומטית X ימים לפני `rsvp_deadline`.

### תבניות הזמנה
- כל תבנית היא קומפוננטת React תחת `src/templates/` שמקבלת את האירוע ומציגה: מדיה, כותרת, תאריך ושעה, מיקום, ספירה לאחור, כפתורי ניווט ויומן, קישור מתנה, וטופס הרשמה.
- קובץ רישום `src/templates/registry.ts` עם מזהה, שם ופלטת צבעים לכל תבנית.
- 10 תבניות: קלאסי, מינימלי, פרחוני, כהה, זהב, ילדים, עסקי, טכנולוגי, חגיגי, רומנטי.
- העלאת מדיה: JPG/PNG/WebP/GIF עד 10MB, נשמר ב-Supabase Storage.

### כפתורי פעולה בדף ההזמנה
- **Waze:** `https://waze.com/ul?ll=LAT,LNG&navigate=yes`
- **Google Maps:** `https://www.google.com/maps/dir/?api=1&destination=LAT,LNG`
- **יומן:** קובץ `.ics` מהשרת + קישור Google Calendar
- **ספירה לאחור:** קומפוננטת client

## תכנית עבודה

1. `create-next-app` עם TypeScript, Tailwind, App Router, ESLint

## אימות
- **מקומי:** `npm run dev` מול פרויקט Supabase לפיתוח
- **זרימת מוזמן:** קבלת מייל הזמנה, פתיחת הקישור האישי, אישור הגעה, בדיקה שהסטטוס התעדכן; הרשמה חוזרת עם אותו טלפון מעדכנת ולא מכפילה
- **זרימת עובד:** login, יצירת אירוע, ייבוא מוזמנים מ-Excel, שליחת מייל בדיקה, שליחה לכולם, לחיצה על וואטסאפ ובדיקת ההודעה, ייצוא Excel
- **תזכורות:** הפעלה ידנית של `/api/cron/reminders` ובדיקה שהמיילים נשלחו ונרשמו ביומן
- **RTL ושפות, מובייל, פריסה:** כמו ברפו המקור (Vercel Preview לכל PR, Production מ-main)

## הנחות וסיכונים
- Gmail רגיל מוגבל לכ-500 מיילים ביום ועלול לסמן שליחה המונית כספאם. לאירועים גדולים צריך Resend (או ספק דומה) עם דומיין מאומת של העסק.
- `wa.me` דורש לחיצה ידנית לכל מוזמן. שליחה אוטומטית בוואטסאפ דורשת WhatsApp Business API (עלות לכל הודעה ואישור תבנית מ-Meta).
- טלפונים נשמרים בפורמט בינלאומי (972...) לטובת `wa.me`; הטופס והייבוא מנרמלים אוטומטית.
- הקישור הכללי ציבורי ולכן חשוף להרשמות מזויפות. rate limit + מחיקה ידנית מספיקים בשלב זה; אפשר לסגור את הקישור הכללי ולעבוד רק עם קישורים אישיים.

## לקחים מהמימוש ברפו המקור
- שם עבדו בסוף עם Next.js 16 (בו `middleware` הוחלף ב-`proxy.ts`), `exceljs` במקום `xlsx`, ו-Gmail במקום Resend.
- ב-Vercel Hobby ה-cron רץ פעם ביום בלבד, ולכן התזכורות נשלחות לפי חלון של 24 שעות.
- ההרשמה הציבורית עוברת דרך פונקציית SQL (`inv_register`) ולא דרך service role ישירות, מה שמצמצם את החשיפה של מפתח השרת.
